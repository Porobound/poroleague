# Deploy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the app as a Docker image to GHCR on every push to `main`, run it on Proxmox with a cloudflared sidecar, migrations on start, nightly SQLite backups.

**Architecture:** Two-stage Dockerfile (`node:24-slim`): build stage runs `npm ci && npm run build && npm prune --omit=dev`; runtime stage holds `build/`, prod `node_modules`, `drizzle/` and `scripts/migrate.ts`. The container runs `migrate.ts` (drizzle-orm's migrator, same `__drizzle_migrations` table as `drizzle-kit migrate`) then `node build`. `compose.yaml` pairs the app with `cloudflared` (token-based tunnel, no open ports). The DB lives in a bind-mounted `./data`, so a host cron job backs it up with `sqlite3 .backup`.

**Tech Stack:** Docker, Docker Compose, GitHub Actions (`docker/build-push-action`), Cloudflare Tunnel, sqlite3 CLI.

**Decisions (made in planning, owner can overrule):**

- `drizzle-orm` moves to `dependencies`: the migrate script needs it at runtime, and `npm prune --omit=dev` would drop it. adapter-node then leaves it external instead of bundling it, which changes nothing at runtime.
- Migrations run from a separate `scripts/migrate.ts` before the server starts, not inside `db/index.ts`: `vite build` imports server modules, and dev keeps `npm run db:migrate`.
- Bind mount `./data:/data` instead of a named volume, so the host's cron can read the file directly. The container runs as `node` (uid 1000), so `data/` must be owned by 1000.
- Off-box copy is the host's job (Proxmox backup or rclone): the script only writes dated local copies and keeps 14.
- Build stage installs `python3 make g++`: better-sqlite3 13 compiles from source. Build copies `.env.example` to `.env` because SvelteKit validates env vars at build; real values come at run time.
- CI only builds and pushes. Type-check and tests stay a local/PR habit; add a CI job when there are other contributors.
- `ORIGIN` comes from `.env` (adapter-node reads it). Tunnel hostname → `http://app:3000` is set in the Cloudflare dashboard.

Expected: `package.json` lists `drizzle-orm` under `dependencies`, not `devDependencies`.

- [ ] **Step 2: Write the script**

```ts
import Database from 'better-sqlite3';
import { drizzle } from 'drizzle-orm/better-sqlite3';
import { migrate } from 'drizzle-orm/better-sqlite3/migrator';

if (!process.env.DATABASE_URL) throw new Error('DATABASE_URL is not set');

const client = new Database(process.env.DATABASE_URL);
migrate(drizzle(client), { migrationsFolder: 'drizzle' });
client.close();
```

- [ ] **Step 3: Verify on a fresh DB, twice (second run is a no-op)**

Run: `DATABASE_URL=$SCRATCH/m.db node scripts/migrate.ts && DATABASE_URL=$SCRATCH/m.db node scripts/migrate.ts && sqlite3 $SCRATCH/m.db "select count(*) from __drizzle_migrations; .tables"`
Expected: count `2`, all schema tables listed.

- [ ] **Step 2: `Dockerfile`**

```dockerfile
FROM node:24-slim AS build
# better-sqlite3 compiles from source.
RUN apt-get update && apt-get install -y --no-install-recommends python3 make g++ && rm -rf /var/lib/apt/lists/*
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
# Build validates env vars; real values come at run time.
RUN cp .env.example .env && npm run build && rm .env && npm prune --omit=dev

FROM node:24-slim
WORKDIR /app
ENV NODE_ENV=production DATABASE_URL=/data/poroleague.db
COPY --from=build /app/package.json ./
COPY --from=build /app/node_modules node_modules
COPY --from=build /app/build build
COPY drizzle drizzle
COPY scripts/migrate.ts scripts/
RUN mkdir /data && chown node:node /data
USER node
EXPOSE 3000
CMD ["sh", "-c", "node scripts/migrate.ts && exec node build"]
```

- [ ] **Step 3: Build and smoke-test**

Run: `docker build -t poroleague:dev .`, then run it with a scratch data dir owned by uid 1000, `--env-file .env`, `-e ORIGIN=http://localhost:3000 -p 3000:3000`, and `curl -sI http://localhost:3000/`.
Expected: build succeeds; logs show no error; curl returns `200`; `data/poroleague.db` exists with migrations applied. Stop and remove the container.

### Task 3: Compose with cloudflared + backup script

**Files:**

- Create: `compose.yaml`, `scripts/backup.sh`
- Modify: `.env.example`, `.gitignore` (`/data`, `/backups`)

- [ ] **Step 1: `compose.yaml`**

```yaml
services:
  app:
    image: ghcr.io/porobound/poroleague:latest
    restart: unless-stopped
    env_file: .env
    environment:
      DATABASE_URL: /data/poroleague.db
    volumes:
      - ./data:/data

  tunnel:
    image: cloudflare/cloudflared:latest
    restart: unless-stopped
    command: tunnel --no-autoupdate run
    environment:
      TUNNEL_TOKEN: ${TUNNEL_TOKEN}
    depends_on:
      - app
```

- [ ] **Step 2: `scripts/backup.sh`** (executable)

```sh
#!/bin/sh
# Nightly from the host's crontab: 0 4 * * * /opt/poroleague/scripts/backup.sh
set -eu
cd "$(dirname "$0")/.."
mkdir -p backups
sqlite3 data/poroleague.db ".backup backups/poroleague-$(date +%F).db"
find backups -name 'poroleague-*.db' -mtime +14 -delete
```

- [ ] **Step 3: `.env.example`** — append:

```

```

### Task 4: GitHub Actions → GHCR

**Files:**

- Create: `.github/workflows/image.yml`

- [ ] **Step 1: Workflow**

```yaml
name: image

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  packages: write

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
      - uses: docker/build-push-action@v6
        with:
          push: true
          tags: |
            ghcr.io/porobound/poroleague:latest
            ghcr.io/porobound/poroleague:${{ github.sha }}
```
